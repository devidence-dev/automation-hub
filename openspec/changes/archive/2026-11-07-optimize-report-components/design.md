# Design

## Context

See proposal.md for motivation. The front-end lives in `internal/services/depreport`: templ components, `assets/input.css` (Tailwind v4 standalone, Lightning CSS minifier), one inline `assets/report.js`, and generated `*_templ.go` and `assets/depreport.min.css` (committed, regenerated by `scripts/generate-depreport-assets.sh` through `gate`). The golden `internal/handlers/testdata/golden/document.html` is compared byte for byte, so every step regenerates it with `UPDATE_GOLDEN=1`.

Measured baseline (fixture, 54 entries; CSS experiments are real builds, HTML figures are simulations on the golden file):

| Item | Today | Target |
|---|---|---|
| Document | 170,638 B | at most 130,000 B (simulated about 111 KB) |
| Compiled CSS | 21,474 B | at most 22,000 B (leaks give -2.5 KB, new utilities add about 1 KB) |
| Entry row | 1,857 B | at most 1,000 B (simulated about 800 B) |

`styles_test.go`, `components_test.go`, `document_view_test.go` and `document_test.go` pin class strings and minified CSS fragments. The existing main spec says "exactly two inline scripts" in "Self-contained document", but the document and `TestDocumentStaticBehavior` have one. That is stale spec text, not touched here.

## Goals / Non-Goals

**Goals:**
- Behavior-level tests that survive refactors, written before any refactor and passing on today's output.
- Smaller markup and CSS with the same look, except the visible changes listed in the spec.
- Fix the audited accessibility gaps.

**Non-Goals:**
- Steps outside the seven groups: tokenizing text sizes, radii, spacing and the `sm:` breakpoint; naming and file layout (`ExportAction`, `CopyButton` file, `TabList`/`TabPanels`, `Head`, font URL const); custom preflight (-3.2 KB); `light-dark()` token dedupe (-1.8 KB). They are possible follow-ups.
- Rejected for being over-engineering: SVG sprite (`<symbol>`/`<use>`, about 7 KB more, shadow-tree styling, conflicts with the test that forbids `href=`); removing `data-yaml` (8.4 KB, needs a JS YAML writer); JS minifier or comment stripping; client-side row rendering; CSS-only tabs or theme radios; Invoker Commands; jsdom or Playwright; a Go class builder; `@apply`; replacing `<details>` or `<dialog>`; dropping Google Fonts; no-JS fallback.

## Decisions

**D1. Tests first, then refactor.** Group 1 adds tests that assert behavior, not class names, and pass today:
- Class coverage both ways: every class of the rendered fixture resolves to a selector of `ReportCSS` (Tailwind-escaped) or to an allowlist of JS hooks (`no-anim`); every class selector of `ReportCSS` is used by the fixture or allowlisted. This is what finds `.ring` and `.inline`.
- JS markup contract: a regexp extracts the selector strings of `querySelector*`, `closest`, `matches` and `getElementById` from `report.js`; each must match the fixture. This would have caught the dead `data-pill-group`.
- Semantic checks: every `<button>` has `type` and an accessible name; every `<svg>` is `aria-hidden` or named; `aria-controls` and `aria-labelledby` targets exist; one `<h1>`.
- Contrast pairs computed from the tokens, extended to `--muted-2`, the selected count and `tone-fg` on the blended `tone-bg`. Today the new pairs are recorded as known failures (explicit expected-fail list) and removed in group 6.
- Size budgets with a table of ceilings. They start at today's sizes plus 1% and are lowered in groups 2 to 5 to the final values of the spec.
Alternative: only fix the existing tests as they break. Rejected: nothing would prove the refactor kept behavior.

**D2. Pinned tests are rewritten with the step that breaks them,** from class strings to roles, `data-*` hooks and attributes. Tests of compiled CSS keep their intent (pointer cursor, enabled-only hover, dialog width and centering, unprefixed `backdrop-filter`, hidden attribute) but match the new rule shapes. Golden stays byte-exact; it is regenerated per step and each step reviews its diff.

**D3. Utilities, not components, for repeated styling.** `@utility icon`, `copy-btn`, `chip`, `dep-row`, `glass-pill`, `dot-glow` and `nums` in `input.css`, with nested selectors for children (`dep-row > code`). Tone colors join `@theme inline` (`--color-tone`, `--color-tone-fg`, `--color-tone-bg`) so `.swatch` and the inline `bg-[var(--tone)]` collapse into `bg-tone`; `.bar-seg` stays for `min-width`. The focus ring (`outline-2 outline-offset-2 outline-accent` on `:focus-visible`) and the `transition-colors` duration move into `btn`. `shadow-*` and `tabular-nums` are replaced by plain declarations, which removes 19 `@property` rules (measured: 21,474 to 18,991 B). Comment words that Tailwind scans as classes (`ring`, `inline`) are reworded and the class-coverage test guards them. Alternative: `@apply` or more templ wrappers; rejected, since the project already uses `@utility` and `@apply` is discouraged in v4.
Values stay identical: the copied declarations replicate today's computed styles, so only the focus ring on tab and theme buttons and the colors in the spec change.

**D4. Icons.** `Icon` keeps `name` and `class`, emits only `viewBox` and `aria-hidden`, and the `icon` utility sets 14px size, `fill:none`, `stroke:currentColor`, `stroke-width:1.3` and round caps and joins. Per-path overrides (`stroke-width` 1.6 and 1.7, the `system` half circle fill) stay as presentation attributes. Redundant `size-3.5`, `width`, `height` and `focusable` go. The raw file icon in `FileGroup` becomes `Icon("file")`, so every svg goes through one component. Estimated -16.5 KB.

**D5. Document-level constants.** `data-copied-text` and `data-copied-before` move to one element (the live region outside the dialog, `#copy-status`), and `report.js` reads them when it flashes a button; the export dialog keeps its own `data-copied-text`. `CopyView` shrinks to `Value` and `Label`; `EntryView` drops `CurrentLabel` and `NewLabel`, rendered from the document labels. `labelSet` splits in two: `chromeLabels` (rendered by templates) and the builder-only labels. `ErrorsCard` takes `ErrorsView{Heading, Chip, Rows}` and `Header` takes `HeaderView`, replacing the whole `documentView` (ISP). The stale comment on `RepoGroupView.Repo` is fixed. The `title` that duplicates `aria-label` on copy buttons stays (it is the tooltip); the `title` duplicating the visible path goes.

**D6. Accessibility.** `<main>` wraps tabs, panels and errors card; entries become `ul role="list"` and `li` (preflight removes the bullets, so `role` keeps the semantics in Safari); the tablist gets `aria-label` from the new key `document.tabs.label` (`KeyDocTabsLabel`, added to `allKeys`; the catalog tests check it against `default.yaml`); `role="status"` replaces `role="status" aria-live="polite"`; the distribution bar gets `aria-hidden` because the legend has the numbers. `color-scheme` is declared on `:root`, on the system-dark block and on both `data-theme` blocks (about 100 B). Contrast: `--muted-2` becomes `#5F6F7C` (light) and `#7D94A4` (dark); the selected count uses new tokens `--count-on-bg: #0A63C2` and `--count-on-fg: #FFFFFF` in all schemes (5.87:1) instead of `--minor` and `--on-minor` (3.65:1). `--muted-2` as the file-icon stroke is a graphic and stays at 3:1 or better. Alternative for `--muted-2`: use `--muted` for the folder text; rejected because the folder and the file name lose their visual split. The new greys are close to `--muted`, so the split is subtler; the user confirms the shades.

**D7. JS cleanup, behavior unchanged.**
- Drop guards that cannot fail (`movePill` nulls, `showTab`/`focusTab` bounds, `onTabKey` index, `instanceof Element`, `announce` null region, `copyBtn?.`, `typeof matchMedia`, `shown.animate`) and fix the header comment ("every DOM query is guarded"). The guards for a missing dialog or export button stay, because a report with nothing pending has none.
- Remove the initial `applyTheme("system")` (the server renders that state), the explicit `indeterminate = false`, the duplicated `choice` test in `applyTheme`, and `STATUS_ID`.
- `copyAndFlash(text, btn)` replaces the two copies of `copyText(...).then(ok => ok && flash(...))`.
- Pills: `data-pill-group` is used (`closest("[data-pill-group]")`) instead of `parentElement` guesses; the window `resize` listener, the `fonts.ready` call and the initial placement are replaced by a `ResizeObserver` on the tab and theme buttons, which fires on observe, on resize, zoom and font load. Reads happen before writes in `movePill`, and `no-anim` is set on the group, not on `<html>`.
- Panel animation moves to CSS: `@keyframes panel-in` with `--dx`, applied to `[data-panel][data-dir]:not([hidden])` under `prefers-reduced-motion: no-preference`; JS only sets `data-dir` before unhiding. Timing stays 420 ms, 24px, blur 4px to 0, `--ease`, as the "Motion" requirement states, and there is no animation on first load. `reduceMotion()` stays only for the view transition of the theme change; the CSS reduced-motion rule already neutralizes it, and the JS check avoids creating the transition.
- The `close` handler that refocuses the opener stays unless a browser check shows the native restore works everywhere the report is opened; it is cheap and harmless.
- `startViewTransition(...)` gets a `.finished.catch(() => {})` so a skipped transition leaves no unhandled rejection.
Alternative: rewrite wiring as one delegated handler. Rejected as churn without gain.

**D8. Regeneration.** Each task that touches `*.templ` or `input.css` runs `scripts/generate-depreport-assets.sh` (`gate templ generate`, `gate tailwind ... --minify`) and, for markup or CSS, `UPDATE_GOLDEN=1 go test ./internal/handlers/ -run TestGoldenBaseline` in Docker, then reviews the golden diff. `scripts/verify.sh` runs the drift check.

## Risks / Trade-offs

- [Utility CSS drifts from today's computed styles] → the class-coverage test, the golden diff review per step and the browser check in 4.6 (user).
- [Moving `data-copied-*` breaks copy feedback] → a Go test for the markup contract (the attributes exist once) and 5.5 (user) for the real browser.
- [`ResizeObserver` or CSS animation misplaces the pill or changes timing] → 7.6 (user) browser check of tabs, theme, resize, font load and reduced motion; the pills are the one behavior with no automated test (no JS harness, no new dependency).
- [Darker `--muted-2` and count badge change the look] → listed in the spec; user confirms the shades before 6.3.
- [Size budgets block legitimate growth] → they are test constants with a message; raising one is a deliberate edit.
- [Tests keep pinning classes] → D2 rewrites them at the step that breaks them, not later.

## Migration Plan

Seven groups, each leaves the repo green and committable on its own. No config or data migration. Rollback is reverting the commit of a group; the generated files are part of the same commit. Nothing is committed without the user's confirmation.

## Open Questions

- Exact final shades of `--muted-2` and the count badge (proposed in D6); a different value only changes constants and the spec scenario.
